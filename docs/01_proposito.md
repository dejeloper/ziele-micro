# Propósito del proyecto

## Idea central

Crear un sistema de descubrimiento y validación de demanda para construir software basado en problemas reales.

La premisa es simple:

> No construimos productos para buscar usuarios. Construimos productos alrededor de problemas que ya están siendo expresados por suficientes usuarios.

El proyecto parte de una convicción: el principal riesgo para un ingeniero de software no siempre es la capacidad de construir una solución, sino construir algo que nadie necesita suficientemente.

Por eso el proceso se invierte:

**Problema → descubrimiento → evidencia → demanda → validación → solución → software → cliente**

## Qué queremos descubrir

El proyecto busca dar voz a personas y empresas que enfrentan problemas operativos, especialmente aquellos que:

- consumen tiempo;
- cuestan dinero;
- generan esfuerzo innecesario;
- dependen de procesos manuales;
- producen errores;
- dificultan tomar decisiones;
- generan esperas;
- requieren consolidar información;
- dependen de herramientas desconectadas;
- o podrían resolverse mediante mejores procesos, automatización o software.

No se busca que el usuario diseñe un software.

Se busca comprender qué está intentando hacer, qué le impide hacerlo mejor y qué consecuencias tiene ese problema.

## Principio fundamental

El usuario declara un problema; nosotros lo investigamos.

La solución que el usuario imagina no debe considerarse automáticamente la solución correcta.

El proceso debe diferenciar entre:

1. problema declarado;
2. problema observado;
3. impacto económico;
4. impacto operativo;
5. frecuencia;
6. solución actual;
7. intentos anteriores;
8. solución imaginada por el usuario;
9. solución propuesta por nosotros;
10. evidencia de demanda;
11. intención de prueba;
12. intención de pago.

## Qué significa validar

No basta con preguntar si alguien quiere una solución.

La demanda debe evaluarse por comportamiento.

Una señal débil es:

> "Me interesa."

Una señal más fuerte es:

> "Quiero probarlo."

Una señal aún más fuerte es:

> "Quiero participar en el piloto."

La señal comercial más fuerte es:

> "Estoy dispuesto a pagar."

Por tanto, el proyecto busca medir tanto lo que las personas dicen como lo que están dispuestas a hacer.

## Visión

Construir una máquina repetible capaz de:

**Escuchar problemas → entenderlos → destilarlos → encontrar patrones → validar demanda → construir soluciones → regresar a quienes levantaron la mano.**

El objetivo inicial no es crear una plataforma sofisticada.

El objetivo inicial es demostrar que este ciclo funciona con personas reales y problemas reales.
