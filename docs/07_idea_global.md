# Idea global

## Nombre conceptual

**El Micrófono de la Demanda**

Nombre conceptual para representar la idea de abrir un canal donde personas y empresas puedan expresar problemas reales y donde esos problemas se conviertan, mediante descubrimiento y validación, en oportunidades para construir software.

## La idea

El proyecto parte de una premisa:

> **No construimos productos para buscar usuarios. Construimos productos alrededor de problemas que ya están siendo expresados por suficientes usuarios.**

La empresa no comienza preguntando:

> "¿Qué software quieres?"

Comienza preguntando:

> **"¿Qué problema estás teniendo?"**

Y, especialmente:

> **"¿Qué estás haciendo manualmente que te está costando tiempo, dinero o esfuerzo?"**

## El micrófono

El micrófono es el mecanismo para darle voz al problema.

La persona puede expresarse libremente mediante una conversación natural, principalmente por WhatsApp.

Puede utilizar:

- texto;
- audio;
- imágenes;
- documentos;
- cualquier forma de comunicación disponible en el canal.

No se obliga al usuario a hablar en términos técnicos.

## Descubrimiento

La conversación busca descubrir el problema real.

La persona puede llegar diciendo:

> "Necesito un programa para hacer X."

Pero el descubrimiento puede revelar:

> "Realmente necesitas reducir el tiempo de elaboración de informes."

La solución propuesta por el usuario no se considera automáticamente correcta.

La empresa busca comprender el proceso antes de diseñar la solución.

## Destilación

La conversación se transforma en conocimiento estructurado.

Se separan:

- problema declarado;
- problema observado;
- contexto;
- frecuencia;
- impacto económico;
- impacto operativo;
- herramientas actuales;
- soluciones existentes;
- intentos anteriores;
- solución imaginada;
- solución propuesta;
- personas afectadas;
- intención de prueba;
- intención de pago.

La IA funciona como interfaz y herramienta de estructuración.

La conversación es humana.

La información resultante es estructurada.

## Validación

No se mide únicamente cuántas personas dicen querer una solución.

Se observa qué están dispuestas a hacer.

La progresión es:

**interés → contacto → conversación → participación → prueba → compromiso → pago.**

La demanda se considera más fuerte cuando el comportamiento confirma las declaraciones.

## Agregación

Muchas personas pueden describir el mismo problema de formas diferentes.

El sistema busca convertir:

**muchas expresiones → pocos problemas subyacentes → oportunidades de producto.**

No se construye un software por cada solicitud.

Se construyen soluciones alrededor de problemas recurrentes y suficientemente importantes.

## Aporte de valor

El usuario no entrega información a cambio de nada.

Después de contar su problema recibe una primera orientación útil.

Puede recibir:

- recomendaciones;
- alternativas;
- herramientas;
- cambios de proceso;
- posibles automatizaciones;
- una interpretación diferente del problema.

Si necesita mayor profundidad, puede existir un servicio de análisis más detallado.

## Construcción

Cuando exista suficiente evidencia, se decide construir.

La decisión debe considerar:

- número de personas afectadas;
- frecuencia;
- gravedad;
- coste;
- soluciones actuales;
- intentos fallidos;
- facilidad de resolución;
- capacidad de pago;
- intención de prueba;
- intención de compra.

La construcción ocurre después de la evidencia.

## Primeros clientes

Las personas que expresaron el problema antes de que existiera el producto pueden convertirse en los primeros usuarios y clientes.

Esto crea un ciclo:

**problema → descubrimiento → validación → construcción → primeros clientes.**

## Distribución

El proyecto comienza localmente.

La primera distribución será principalmente humana:

- empresas;
- comerciantes;
- contactos;
- recomendaciones;
- comunidades;
- WhatsApp;
- material físico;
- redes locales.

El objetivo inicial no es escala.

Es aprendizaje.

## Visión a largo plazo

El objetivo es desarrollar un proceso repetible:

**Escuchar → descubrir → destilar → agregar → validar → priorizar → diseñar → construir → distribuir → aprender.**

Con el tiempo, la IA puede automatizar cada vez más partes del proceso.

Pero el activo principal no será la tecnología.

Será la capacidad de comprender problemas reales y convertirlos sistemáticamente en productos que ya tienen una demanda inicial.

## Ventaja potencial

Una landing y un chatbot pueden ser copiados.

La verdadera ventaja potencial se construye con el tiempo:

- conversaciones;
- conocimiento acumulado;
- patrones;
- problemas entendidos;
- soluciones probadas;
- comportamiento de usuarios;
- relaciones;
- reputación;
- primeros clientes;
- capacidad de detectar oportunidades antes que otros.

Por eso el objetivo no debe ser simplemente ser el primero en crear un mecanismo para escuchar.

Debe ser:

> **Convertirse en una empresa excepcionalmente buena escuchando problemas, descubriendo lo que realmente significan y transformándolos en software que las personas ya estaban esperando.**

## Frase central

> **Escuchamos problemas. Destilamos demanda. Construimos soluciones.**
