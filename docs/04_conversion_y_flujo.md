# Estrategia de conversión y flujo

## Objetivo

Convertir una conversación sobre un problema en una relación progresiva con el usuario, sin presionarlo inicialmente para comprar software.

El flujo debe avanzar desde una señal débil hacia señales cada vez más fuertes de compromiso.

## Flujo general

**Landing → WhatsApp → descubrimiento → primera orientación → seguimiento → validación → piloto → solución → pago**

## Etapa 1: descubrimiento

El usuario llega porque tiene un problema.

No se intenta vender.

Se busca entender.

## Etapa 2: primera devolución de valor

Después de comprender el problema, se devuelve algo útil:

- resumen del problema;
- interpretación;
- posibles causas;
- alternativas;
- recomendaciones;
- pequeñas acciones que pueda ejecutar.

La finalidad es demostrar:

> "Contarnos tu problema te aporta algo."

## Etapa 3: clasificación

El problema se clasifica internamente según:

- gravedad;
- frecuencia;
- impacto;
- recurrencia;
- cantidad de personas afectadas;
- calidad de la solución actual;
- intentos anteriores;
- capacidad de pago;
- intención de probar.

## Etapa 4: seguimiento

Cuando el problema sea relevante, se mantiene la relación.

No se debe desaparecer después de capturar la información.

Puede comunicarse:

> "Estamos investigando este problema porque encontramos otras personas con una situación similar."

## Etapa 5: propuesta

Cuando exista suficiente evidencia, se presenta una posible solución.

La propuesta no debe estar condicionada a que el usuario haya pedido exactamente ese producto.

La empresa debe poder decir:

> "Entendimos que pedías X, pero después de analizar tu proceso creemos que el problema principal es Y. Nuestra propuesta sería resolver Y mediante Z."

## Etapa 6: piloto

Los usuarios que expresaron el problema pueden convertirse en primeros participantes.

Aquí se valida:

- uso real;
- utilidad;
- resultados;
- objeciones;
- disposición de pago.

## Etapa 7: conversión

Si la solución genera valor, se convierte en producto o servicio comercial.

La prioridad es que la primera demanda provenga de personas que ya participaron en el descubrimiento.

## Principio de conversión

No se debe optimizar solamente:

> visitantes → leads

Debe optimizarse:

> problemas → problemas comprendidos → problemas validados → usuarios comprometidos → clientes.

La métrica final no es cuántos datos se capturaron.

Es cuántas oportunidades reales de negocio fueron descubiertas.
